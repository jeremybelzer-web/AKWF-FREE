## Patterns to adapt (our words)

### Session / clip matrix
- Grid of launchable idea slots per track → reinterpret as **curiosity matrices** (cover = all curiosities; behind = one curiosity each).
- Scene-like vertical launch → later: suite launch / section launch (defer until heart works).

### Arrangement / playlist
- Linear multi-track timeline as the **user song** surface.
- Dual view: user arrangement in front; **inspiration** arrangement behind via swipe (web).

### Detail / magnify / piano roll
- Bottom or focus pane shows selected clip/lane detail → **curiosity lane editor** + node selection.
- Zoom granularity for form editing (Sketch-class).

### Devices / mixer strip
- Per-track device chain → v0 only: automation lanes + tiny built-ins later; no 3rd-party plugin host required for heart.

### Browser / library
- Content browser → Essence Shelf / curiosity templates / user suites (our naming).

### Song Sketch–class form tools (from Jeremy’s product references, not vendor manuals)
- Section/form sketching UX → generalize to **any curiosity**, any zoom, 1..N tracks.

### Chord Changes–class harmonic tools
- Clip-synced progression exploration → extend to whole song, multi-key, curiosity automation redraw.

## Patterns to reject / defer

| Pattern | Why defer |
|---------|-----------|
| Full Live/FL feature parity | Blocks heart demo |
| Deep mixer / routing matrices | Not needed for curiosity leadership |
| Third-party plugin APIs | Out of heart path |
| Dual-skin / every-engine-own-window chrome | Layout tax |
| Huge theory corpora UIs (Wanderer/Orbits-scale) | After heart ships |
| Unlicensed “extract this hit” public libraries | Legal/product risk |
| Exact Ableton/FL menu clone / trademarks | IP / confusion risk |
